安装与升级 ​

本文面向负责安装的人：通常是开发同事，有经验的测试或产品同事也可以按步骤完成。每台机器只装一次（装在运行 agent 平台的那台机器上），之后这台机器上所有项目的对话都能使用 /laoshi。

laoshi 目前支持两个 agent 平台：

平台说明
Paseo 0.11
--platform paseo		步骤 agent、工作区、服务、定时消息都由 Paseo daemon 提供
DeepSeek Harness（dsh）
--platform dsh		步骤 agent 和定时消息由 laoshi 的 dsh 插件提供；工作区和服务用 laoshi 的内置实现（git worktree、.laoshi/services.json）

1. 安装布局 ​

程序和本机配置分开存放。升级只替换程序，配置不动。

text
<npm 全局目录>/laoshi/     程序（全局目录不可写时在 ~/.laoshi/npm 下）
~/.laoshi/                 安装根（LAOSHI_HOME 可以换位置）
├── config.json            安装级配置：平台、各角色的模型
├── install.json           安装记录（--check、--uninstall 用）
├── bin/laoshi(.cmd)       laoshi 命令（不在 PATH 时用）
├── prompts.local/         本机提示词覆盖（可选）
└── notifiers/             外部通知模块（可选，见第 10 节）
<skill 目录>/laoshi*/      按平台渲染的 skill，带 .laoshi-install.json

skill 装到哪里由平台决定：

平台skill 目录
Paseo~/.agents/skills（Codex、Pi、OpenCode 等读取），~/.claude 存在时还有 ~/.claude/skills
dsh$DSH_HOME/skills（默认 ~/.dsh/skills）；dsh 插件装在 $DSH_HOME/profiles/<profile>/node_modules/laoshi-dsh-plugin 并挂载到 cordis.patch.yml

--target <目录> 可以另外指定 skill 目录（可以写多次）。Windows 上 ~ 即 %USERPROFILE%。安装器不使用符号链接，不需要管理员权限；在 Windows 上它只启动 node 和 cmd.exe，不会启动 PowerShell。

2. 前置条件 ​

项目要求如何确认
Node.js22.19 或更新node -v
npmNode.js 自带；公司网络用镜像（见第 3 节）npm -v
git近期版本git --version
平台Paseo 0.11 的 daemon 在运行；或已装好 dsh（dsh 命令可用，或知道它的 bin.js 位置）Paseo：能在桌面端或 http://localhost:6767/ 对话；dsh：能在网页端对话
模型Paseo：Claude Code、Codex、OpenCode、Pi 至少一种已在 Paseo 中登录；dsh：对话用的模型能正常回答用它开一个对话

3. 首次安装 ​

一步安装（推荐）。 只需要 Node.js 和能访问的 npm 源：

bash
npx -y @yiyi_zhang/laoshi@latest install --platform dsh      # 或 --platform paseo

它依次：检查 Node.js、npm 和 git；确定 npm 源；npm install -g 这个版本（全局目录不可写时装到 ~/.laoshi/npm，不需要 sudo）；然后运行装好的那份程序的 laoshi install，完成安装级配置、skill 和平台的设置。npx 的临时目录会被清理，所以安装记录和 skill 都指向 npm 装好的那份。再次运行就是升级。

指定版本：npx -y @yiyi_zhang/laoshi@0.1.1 install --platform dsh。

公司内网（只有 npm 镜像）。 加上镜像地址：

bash
npx -y --registry=https://npm.example.internal/ @yiyi_zhang/laoshi@latest install --platform dsh
  • 镜像地址会保存为本机的 npm 源（屏幕上会写出原来的值），以后 laoshi upgrade 也从镜像取。只想这一次用镜像时加 --no-save-registry。本机原本就配好了镜像时不用写 --registry。
  • 镜像上还没有这个版本（同步有延迟）时会直接说明，稍后再运行，或请管理镜像的同事同步 laoshi。
  • 文档：装好后运行 laoshi docs，在本机打开和这个版本一致的文档站点，不需要外网。

完全离线（连 npm 镜像也没有）。 用带依赖的离线安装包，步骤见内网安装与验证。

已经有程序目录时（git 克隆、解压的安装包）：在程序目录中 npm ci --omit=dev，再运行 node bin/req.mjs install --platform <平台>。

安装选项 ​

选项含义
--platform <paseo|dsh>装到哪个平台。第一次安装时要写，之后沿用安装记录；和已装的平台不一致时会停下
--home <目录>安装根，默认 LAOSHI_HOME 或 ~/.laoshi
--target <目录>另外把 skill 装到这个目录
--force覆盖同名的、不是 laoshi 装的 skill（默认跳过并列出）
--check只检查，不改动（也可以用 laoshi check）
--dry-run演练：显示要做的事，不写文件
--uninstall卸载（见第 8 节）
--registry <地址>、--no-save-registry只用于一步安装和 laoshi upgrade：这次用的 npm 源，是否保存
dsh：--dsh-home <目录>dsh 的数据目录，默认 DSH_HOME 或 ~/.dsh
dsh：--profile <名称>插件装进哪个 profile，默认 web
dsh：--dsh-bin <路径>dsh 的 bin.js，dsh 不在 PATH 中时写；dsh plugin add 失败时安装器直接复制插件
dsh：--approvals ask|allow步骤 agent 的审批请求：ask 交给人（默认），allow 直接批准一次

同名 skill 的处理：带 .laoshi-install.json 标记的是 laoshi 装的，会被更新；paseo-req-kit 装的（带 .req-kit-install.json）和别人放的都不覆盖，安装器会列出它们，确认后再用 --force。

4. 配置模型 ​

各角色（builder 实现、reviewer 评审等）用的模型写在 ~/.laoshi/config.json 的 agents 中，项目的 .laoshi.json 可以覆盖。写法因平台而异。

Paseo ​

运行 laoshi configure（逐项选择）或 laoshi configure --auto（按推荐选好：两个不同厂商的模型分别做 builder 和 reviewer，都用免确认模式）。

推荐引用 Paseo 的 agent profile。 在 Paseo 的 设置 → 本机 → Agents → Agent profiles 中建好"实现""评审"等 profile，配置中只写名称，之后换模型只需在 Paseo 中改 profile：

json
"agents": {
  "builder":  { "platformProfile": "实现" },
  "reviewer": { "platformProfile": "评审" }
}

也可以直接写各项设置：

字段含义
provider<Paseo 中的 provider ID>/<模型 ID>，只在第一个 / 处拆分
modeIdagent 的模式。必须选不会停下来等待批准的模式；没有模式的 agent 不写
featureValuesagent 的功能开关，目前只有 OpenCode 需要
thinkingOptionId可选，思考强度
agentprovider 写法无人值守的设置
Claude Codeclaude/<模型 ID>"modeId": "bypassPermissions"
Codexcodex/<模型 ID>"modeId": "full-access"
OpenCodeopencode/<上游>/<模型 ID>"modeId": "build" 加 "featureValues": { "auto_accept": true }
Pipi/<上游>/<模型 ID>不写 modeId

聊天 agent（使用者对话的那一个）的用法：

agent如何触发
Claude Code、OpenCode/laoshi 我想……
Pi/skill:laoshi 我想……
Codex直接说"用 laoshi 帮我……"

聊天 agent 需要能执行命令和访问本机网络（流水线要连接 daemon）。

dsh ​

provider 写成 <dsh 的提供方>/<模型>，这个角色的步骤就用它；thinkingOptionId 作为推理强度。dsh/chat-model 表示用对话的模型（安装器的默认值）：

json
"agents": {
  "builder":  { "provider": "dsh/chat-model" },
  "reviewer": { "provider": "deepseek/deepseek-reasoner", "thinkingOptionId": "high" }
}

laoshi doctor 列出 dsh 中可用的模型并逐个角色检查。在 dsh 的对话里输入 /laoshi 我想…… 开始；发起的对话由 dsh 提供的 DSH_SESSION_ID 识别。更多见在 DeepSeek Harness 上使用。

5. 体检和冒烟测试 ​

bash
laoshi doctor --no-project    # 安装、配置、平台、模型
laoshi doctor                 # 在项目目录中：再检查这个项目

全部是 ✓ 或只有 ⚠ 即可继续，✗ 的项按提示处理。然后在一个测试项目中完整跑一遍：新开对话，输入 /laoshi 在 README 末尾加一行版权声明，应走快速档，收到进展和完成通知，功能目录中各产物齐全，工作分支上有本地提交。

Paseo 另有冒烟测试（在程序目录中运行）：npm run smoke -- check 启动两个角色各一个小 agent，确认能写文件、能执行命令、不停下等权限。

6. 升级和回退 ​

bash
laoshi upgrade                       # 最新版本
laoshi upgrade 0.1.0                 # 指定版本（也用于回退到旧版本）
laoshi upgrade --registry <镜像地址>  # 换 npm 源

它从 npm 装好新版本，再运行新版本的 laoshi install，沿用安装记录中的平台和选项。配置、项目文件和功能目录不变。升级会原地替换程序文件，请在没有流水线运行时升级（laoshi list 查看）。

平台（Paseo、dsh）或 agent 升级之后，运行 laoshi doctor 确认版本在支持范围内、配置中的模型仍然存在。

7. 和 paseo-req-kit 共存 ​

laoshi 是从 paseo-req-kit 抽出的平台无关版本，两者可以装在同一台机器上：

  • 安装根不同（~/.laoshi 和 ~/.req-kit），命令不同（laoshi 和 req；laoshi 也提供 req 别名，npm 全局安装时后装的那个生效）。
  • 只有 ~/.req-kit 时，laoshi 会读取它；.requirement-pipeline.json 也继续被读取，新项目用 .laoshi.json。
  • 同名 skill 不互相覆盖（见第 3 节）。

8. 卸载 ​

bash
laoshi install --uninstall

删除 laoshi 装的 skill，dsh 上还会移除插件和 cordis.patch.yml 中的挂载。安装根（~/.laoshi）保留；确认不再使用后，npm uninstall -g @yiyi_zhang/laoshi 并手工删除 ~/.laoshi。各项目中的配置文件和功能目录保留，它们本身就是文档。

9. 安全提示 ​

  • 步骤 agent 以免确认模式运行（dsh 上 --approvals allow 时同样），可以在本机执行命令。仓库和本机环境变量中不要放生产凭据；最好用专门的开发机或虚拟机。
  • 口令和密钥只放在环境变量中，不要写进配置文件。
  • 流水线只做本地提交，合并和上线始终由人决定。

10. 接入企业内部 IM（可选） ​

流水线默认只把消息发回发起的对话。希望"需要你决定""开发中断""已完成"等时刻在企业 IM 中也收到时，需要自己实现一个通知模块（laoshi 不内置任何 IM）：

  1. 把程序目录中的 notifiers/im-template.mjs 复制到 ~/.laoshi/notifiers/im.mjs，按其中的 TODO 实现发送（通常是向 IM 机器人的 webhook 发一个 HTTP 请求）。口令放在环境变量中。

  2. 在 ~/.laoshi/config.json（或团队配置）中加上：

    json
    "notifiers": [
  { "module": "~/.laoshi/notifiers/im.mjs", "events": ["blocked", "failed", "completed"], "options": { "webhook": "https://…" } }
]

  3. 运行 laoshi notify-test（可加 --type blocked 等）发一条测试消息。

事件的类型和字段见 contracts/notifier-event.md。通知失败只记日志，不影响流水线。项目配置（.laoshi.json）中的 notifiers 会被忽略。

11. Paseo 的需求插件 ​

在 Paseo 界面里看需求总览、进度和文档的插件目前仍由 paseo-req-kit 提供（req plugin install），计划在 0.1.0 之后迁入 laoshi。
