Paseo Web 与 dsh 真实环境插件走查清单 ​

本清单用于在真实运行的 Paseo Web 端与**内网 dsh（Node 24）**环境中，对 laoshi 插件、共享 Web 需求看板及核心流程扩展进行端到端人工走查。如遇到问题，请记录「结果/截图」并按文末方式打包诊断信息反馈。

1. 前置条件与安装确认 ​

1.1 运行环境 ​

平台支持范围 / 环境要求参考说明
Paseo（Web 端优先）Paseo daemon >=0.11.0 <0.18.0（见根目录 package.json 的 reqKit.paseo）；Node.js >=22安装与升级
DeepSeek Harness（dsh）dsh >=0.2.0 <0.3.0（见 reqKit.dsh）；内网要求 Node 24；Windows 下禁止依赖 PowerShelldsh 适配器说明、内网安装与验证

1.2 安装与插件启用 ​

sh
# 一步安装（以 npm 源为例，自动完成配置、skill 与平台插件部署）
npx -y @yiyi_zhang/laoshi@latest install --platform paseo
npx -y @yiyi_zhang/laoshi@latest install --platform dsh

# 本机已安装后直接刷新单个平台，或用 laoshi upgrade 同步升级全部已并存平台
laoshi install --platform paseo
laoshi install --platform dsh
laoshi upgrade

内网离线安装包部署 dsh 请参考 内网安装与验证。Paseo 默认一并安装/刷新插件（跳过加 --no-plugin）；若 Paseo daemon 在安装时未启动，先启动 daemon 后可执行 laoshi plugin install --yes 完成挂载。若本机需要 Paseo 与 dsh 并存，只需先后对两个平台执行安装命令即可。

1.3 laoshi doctor 期望输出 ​

在测试项目目录运行 laoshi doctor，确认以下关键项均正常（✓）：

  • 配置与核心：配置分层正确；若项目配置开启了 reviewPanel，检查多厂商模型互补性；若有受控流程扩展（extensions），校验 skill 路径存在；若未登记 relatedRepos 且存在同级 git 仓库，应提示可用 /laoshi-setup 自动发现登记。
  • Paseo：显示已连接 daemon 且版本在支持范围内，laoshi 插件已安装并运行。
  • dsh：显示已连接 laoshi dsh 插件（socket 或 Windows 命名管道）、版本在支持范围内、可用模型提供方，以及托管需求看板与页面挂载状态（如 需求看板运行中：http://127.0.0.1:<端口>/，已在 dsh 左侧导航栏「需求看板」中挂载（/laoshi/））。

2. 逐项走查清单 ​

请在 Paseo Web 插件页面与 dsh 托管看板（以及对应项目对话）中依次验证下表每一项：

项目操作期望结果结果 / 截图
1. 总览分组与「需要你处理」（X1）准备至少 1 个处于等待确认方案或业务问题的需求，分别打开 Paseo Web 侧边栏面板与 dsh Web 左侧导航栏 「需求看板」（/laoshi/）dsh 主界面内直接嵌入显示全宽「需求看板」且配色随 dsh 深浅主题同步；顶部切换 需求 / 使用统计 / 配置 正常；首页 Bento KPI 数字准确；「需要你处理」区置顶展示等待时长（等了 …）、紧急程度提示、影响说明与主操作按钮
1b. 全宽详情、执行记录与对话快捷入口在 dsh 内嵌「需求看板」点开需求进入全宽详情页，查看关键决策高亮区、2 列元数据卡片、Markdown/TSV 文档弹窗及 「执行记录」，分别点击某一步的 「查看执行记录 ↗」 与顶部的 「打开需求对话 ↗」；再回到该需求的主对话或子对话顶部栏点击 「需求：<标题>」全宽详情交互与 Paseo 插件对齐；点击步骤可直接切回对应子 agent 的执行对话，点击「打开需求对话 ↗」切回原需求对话；从对话顶部栏按钮可直达内嵌看板中的对应需求详情
2. 基础操作（确认/停止/继续/验证）对对应状态的需求分别执行「确认方案」「停止」「继续」「开始测试验证」（本地或已部署环境）操作二次确认弹窗正常；执行后状态与 6 站放行轨实时更新；「停止」会中断后台进程与当前步骤，「继续」沿用已完成步骤
3. 验收工作台与一键试用（X2）打开已完成或待验收需求详情：Web 看板切至「验收工作台」，Paseo 点「一键试用」「验收清单」点「一键启动试用」返回可访问地址与测试说明；逐条勾选 AC（全部通过或标记不通过+原因）后提交，生成并提交 acceptance.md；点「停止试用」可停止服务
4. 进度预估与预算提醒（X3）本机累计至少 3 个同档位已完成需求后：启动 1 个新需求（接近 budget.tokens），并查看进行中需求详情新需求启动日志给出历史中位数用时/token 与预算提醒；详情页展示已用时长、tokens 及预计剩余时间
5. 联合开发与多仓视图（X7）在配置了 relatedRepos（可选 maxJointRepos > 2）且 spec.md 带 - 联合开发：… 的项目中运行联合需求并打开详情详情页展示每个联合仓库名称、分支、工作区路径与质量门通过状态徽标；/laoshi-setup 能列出同级 git 仓库供勾选
6. 发起改需求（X5）在 Web 看板「变更与接手」页签或 Paseo 详情页点「改需求」，输入变更说明并确认发送原对话收到 【需求开发流水线通知 · 需求方要改需求】 通知；若流水线在运行则引导先停止，按对齐流程更新 spec.md 版本并追加 changes.md
7. 变更历史与转交接手（X5）在 Web 看板「变更与接手」页签或 Paseo「变更历史与负责人」区块展开变更记录、查看 spec.md 提交 diff，并提交「转交」给另一同事列表与详情显示更新后的当前负责人；changes.md 倒序折叠可读；git diff 以绿增/红删高亮显示改动行；.pipeline/owner.json 保留完整转交历史
8. dsh 定时任务 expiresAt通过带到期时间（expiresAt）的预约或测试脚本在 dsh 上创建周期定时任务到达 expiresAt 后 dsh 插件自动取消定时任务（dsh 0.2.2-rc.5+ 调用 schedule.edit，旧版调用 schedule.delete），不再继续触发
9. dsh scheduleNewAgent运行 laoshi digest --schedule "0 9 * * 1" 预约需求总览，再执行 laoshi digest --cancel <ID>dsh 插件新建独立会话并绑定 cron 定时任务，返回 dsh:<sessionId>/<id>；取消后对应定时任务被删除
10. 只读模式拦截在 Paseo 插件设置打开 readOnly（或启动 laoshi board --read-only）后尝试点击操作/验收/改需求/转交按钮界面隐藏写操作表单与按钮；直接调用后端接口（run / /api/action / /api/try / /api/acceptance）也返回只读拒绝，不修改任何状态
11. Windows 受控流程扩展（M3）在 Windows 项目 .laoshi.json 配置 extensions（含 kind: "script" 及双引号参数命令，挂载 after: "handoff"）后运行流水线脚本通过 cmd.exe（不启动 PowerShell）正常执行，注入 LAOSHI_* 环境变量，日志完整写入 .pipeline/extensions/<id>.log

当前已知未接入 dsh 项说明：dsh 的事件流替代轮询与**浏览器能力检测（capabilities）**目前仍按降级路径运行，待在真实 dsh 环境中确认对应插件 API 后再单独补齐。

3. dsh 自动化端到端脚本（可选） ​

如果内网机器已安装 @deepseek-ai/dsh，可先用模拟模型跑通底层链路：

sh
LAOSHI_E2E_DSH=<装有 @deepseek-ai/dsh 的目录> node adapters/dsh/e2e/run-e2e.mjs --worktree

检查全部通过后再结合上表走查真实模型与插件 Web 界面效果。

4. 问题排查与反馈 ​

若走查中任一项未通过或流水线中断，请运行以下命令打包现场信息（日志与配置会自动脱敏），连同走查表结果、页面截图、laoshi doctor 输出一并发给维护者：

sh
laoshi diagnose <需求名称> --out ./diagnose-output
