# 在摸高上使用

本文面向在摸高上使用 laoshi 专家的人：提交专家的人、第一次使用的人、日常提需求的测试、产品、项目经理。laoshi 在摸高上的工作方式和 Paseo、dsh 一样：在对话里把需求谈清楚、写成需求说明并确认，之后由一组 agent 完成方案、实现、评审、验证和报告，每个要拍板的地方都停下来等人。设计见 [mogao-expert](../design/mogao-expert.md)，适配器见 [adapters/mogao](../../adapters/mogao/README.md)。

## 1. 先了解摸高的三个特点

| 特点 | 对使用的影响 |
| --- | --- |
| 每个对话轮次一台新机器，只有 `/data/workspace`（工作区）和 `/data/.aimax` 会保留 | laoshi 装在工作区的 `/data/workspace/.laoshi`，**一个工作区只装一次**；代码库也要放在工作区里（例如 `/data/workspace/<项目>`），否则下一轮就没了 |
| 流水线在对话执行的命令里运行，轮次结束就停下 | 运行期间不要结束这一轮对话；被打断了，下一轮说"继续"，做完的步骤不会重做 |
| 没有定时任务，也不能主动给对话发消息 | 预约启动、定时提醒、自动继续都用不了；进展显示在命令输出里，由对话转告你 |

## 2. 提交专家（维护者做一次）

专家是一组按摸高渲染好的 skill，加一份介绍 `EXPERT.md`。要用**已经发布到 npm 的版本**生成，因为第一次使用时会从内网 npm 镜像安装同一个版本：

```sh
git checkout <版本标签>            # 例如 0.2.0-beta.1
npm install
node adapters/mogao/make-expert.mjs   # 生成 dist-expert/laoshi-expert-<版本>/ 和同名 zip
```

把 `laoshi-expert-<版本>` 里的 skill 按摸高的专家格式提交到平台。包含的入口：

| 入口 | 什么时候用 |
| --- | --- |
| `/laoshi` | 提需求、查进度、继续、验收，日常都从这里开始 |
| `/laoshi-setup` | 项目接入：每个代码库第一次用之前做一次，项目的构建、测试方式变了再做一次 |
| `/laoshi-doctor` | 体检：安装、平台、项目检查是否正常 |
| `/laoshi-retro` | 复盘：把 laoshi 本身的问题整理成报告 |

另外还有方法 skill（访谈、需求说明、验收标准、如实报告等）和原则 skill，由入口按需使用。

## 3. 第一次使用：自动安装

不需要单独的安装步骤。第一次在对话里用 `/laoshi`（或其他入口）时，入口 skill 会先检查工作区里的 laoshi 是不是专家对应的版本，不是就从内网 npm 镜像安装，并写好安装级配置。大约一分钟，之后同一个工作区里的所有对话直接使用；专家换了新版本，下一次使用时自动换上。

装好后的布局：

```text
/data/workspace/.laoshi/
├── npm/node_modules/@yiyi_zhang/laoshi/   程序
├── config.json                            安装级配置（平台 mogao、各角色的模型）
├── skills/                                按摸高渲染的 skill（和专家里的一样）
├── mogao/agents/                          每个步骤 agent 的记录（提示词、输出、工具调用）
└── tools/                                 项目需要、沙箱里没有的工具（自己放）
```

不需要设置 `LAOSHI_HOME`：程序装在安装根的 `npm` 目录里，laoshi 据此找到安装根。

**安装失败时**：把对话里的输出发给开发同事。常见原因是内网镜像还没同步到这个版本（刚发布的版本要等镜像同步），这时可以手动安装：

1. 从 GitHub Release 下载 `laoshi-<版本>.tgz`，上传到 `/data/workspace`。
2. 在对话里执行：

   ```bash
   npm install --prefix /data/workspace/.laoshi/npm --no-audit --no-fund /data/workspace/laoshi-<版本>.tgz
   node /data/workspace/.laoshi/npm/node_modules/@yiyi_zhang/laoshi/bin/req.mjs install --platform mogao --home /data/workspace/.laoshi
   ```

3. 用 `/laoshi-doctor` 体检。

## 4. 项目接入：每个代码库一次

1. 把代码库放到工作区里，例如 `git clone <内网仓库地址> /data/workspace/<项目>`。
2. 在对话里说明项目目录，运行 `/laoshi-setup`。它会在项目根目录生成或更新项目说明、验证方法（实际运行其中的命令）、工作区设置和项目配置，确认后提交。
3. 用 `/laoshi-doctor` 确认项目检查全部正常。

**构建工具**：摸高的沙箱自带的工具很少（例如没有 mvn、gradle），而且每轮的 `PATH` 都会重置。项目要用的工具装到 `/data/workspace/.laoshi/tools/<工具>`，命令里写完整路径。例如 Maven：

```bash
# 解压到 /data/workspace/.laoshi/tools/maven，本地仓库放在 /data/workspace/.laoshi/tools/m2
/data/workspace/.laoshi/tools/maven/bin/mvn -Dmaven.repo.local=/data/workspace/.laoshi/tools/m2 test
```

`/laoshi-setup` 写进 `verify.md` 和 `.laoshi/services.json` 的命令也要这样写。

同一个工作区里的多个代码库共用一份安装，每个代码库各做一次项目接入。

## 5. 日常使用

### 提需求

在项目目录的对话里输入 `/laoshi`，说你要做什么。laoshi 先和你把需求谈清楚，写成需求说明请你确认；确认后流水线开始：方案 → 实现 → 评审 → 验证 → 报告。

### 流水线运行期间

- 启动、继续、确认方案后继续、开始测试验证这几条命令**会一直运行**，直到需要人决定（方案确认、业务问题、等待批准）或做完。对话会持续查看命令输出，把进展转告你。
- 这期间**不要结束这一轮对话**。如果对话轮次结束了（你关掉了对话、或者超过了平台的时限），流水线就停在当时那一步。
- 下一轮在对话里说"继续"（`/laoshi` 会运行 `laoshi resume <需求>`），从停下的地方接着做；做完的步骤不会重做，做到一半的步骤会接上原来的 agent 会话。

### 等待批准

步骤 agent 执行平台规定要批准的命令时（按工作区 `.aimax/config.yaml` 的命令黑名单），这一步会停下。对话会把要批准的操作原样告诉你，问你批准还是拒绝，然后结束这一轮。你下一轮回答"批准"或"拒绝"（可以说明理由），对话运行 `laoshi permission <需求> approve`（或 `deny`），转达决定并接着运行。

laoshi 自己也会拦截危险命令，例如读出平台凭据的环境变量（`echo $XXX_TOKEN`、`printenv`）；工具输出写进日志前会先脱敏。

### 需要以后再做的事

摸高上没有定时任务。laoshi 提示"到时再继续"的事情，到时在对话里说"继续"即可。

### 查进度、验收

随时在对话里问"进度怎么样"（`/laoshi` 会运行 `laoshi status`）。流水线做完后会给出报告和验收清单，验收方式见[使用者指南](使用者指南.md#验收)。

## 6. 配置

安装级配置在 `/data/workspace/.laoshi/config.json`，摸高相关的部分写在 `platform.mogao` 下，一般不用改：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `command` | `aimax` | 平台命令行（不在 `PATH` 中时写完整路径） |
| `dataDir` | `/data` | 平台的数据目录（`aimax -d`） |
| `runTimeoutMinutes` | 240 | 一次 `aimax run` 的上限（引擎另有每一步的时限） |
| `pluginsConfig` | 无 | 给步骤 agent 的 `--plugins-config`，让步骤里也能用平台插件（如知识库） |

各角色默认都用对话的模型（`mogao/chat-model`）。

## 7. 常见问题

| 现象 | 原因和处理 |
| --- | --- |
| 第一次使用装不上 | 内网镜像还没有这个版本，或镜像暂时不通；按第 3 节手动安装 |
| 体检说找不到 `aimax` | 平台命令行不在 `PATH` 中；在 `platform.mogao.command` 写它的完整路径 |
| 流水线停在某一步，对话已经结束 | 正常：下一轮说"继续" |
| 某一步提示"单次运行的上限" | 一次 `aimax run` 超过了 `runTimeoutMinutes`；说"继续"会接着这个步骤的会话做，频繁出现时调大这个值 |
| 构建命令找不到（如 `mvn: command not found`） | 工具没装在工作区或命令没写完整路径；见第 4 节 |
| 想知道某一步 agent 做了什么 | `/data/workspace/.laoshi/mogao/agents/<id>/` 下有它的提示词、输出和工具调用记录 |

## 8. 用量

每次 `aimax run`（每一步、每次续接）平台的系统提示约 1.4 万 token，没有缓存命中。需求越大、评审轮次越多，步骤越多，用量也越大；`laoshi stats` 可以看每个需求的用时和 token。
