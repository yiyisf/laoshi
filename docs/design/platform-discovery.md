# 平台摸底清单

- 用途：在没有平台详细文档时，用几个小实验把 [internal-platform-adapter §6](internal-platform-adapter.md) 的五个问题回答出来。**实验输出就是适配器设计的依据，也是后面探针测试的原型。**
- 谁来做：能在内部平台上运行 CLI 的人（平台使用者即可，不需要平台源码）。
- 预计耗时：1~2 小时。每个实验都用空的临时目录和很短的提示词，用量很小。

## 开始之前

1. 新建一个空的临时目录，所有实验都在里面做，实验结束后整个删掉。
2. 把每次命令的**完整命令行、stdout、stderr、退出码**原样保存到文本文件（例如 `exp1-start.txt`）。不要只写结论。
3. **分享之前先脱敏**：删掉令牌、密码、内部地址里的敏感部分。环境变量只记名字，不记值。

## 实验 0：命令清单

- CLI 的名字和版本。
- 顶层 `--help` 的完整输出，以及和下面这些动作相关的每个子命令的 `--help`：启动任务、查看状态/列表、查看日志或输出、恢复会话、取消请求、取消任务（如果有）。

## 实验 A：引擎能在哪里运行（决定引擎的位置，最先做）

在摸高平台的沙箱里（工作目录 `/data/workspace`）记录：

- `node -v`、`npm -v` 有没有；`npm install` 一个小包能否成功（用已设置好的内网源）。
- 沙箱里能否执行上面的平台命令行（实验 0 的那个）；认证怎么来。
- 启动一个后台进程（例如每 10 秒往文件写一行时间），结束对话后过 5 分钟、30 分钟再看它还活着吗。
- 工作区外的目录（`/tmp`、`$HOME`）在下一次对话里还在吗。
- 4 GB 空间是否够放引擎、依赖和一个多仓库工作目录。

结论决定引擎放在沙箱里、使用者本机，还是服务器（见 [ADR 0006](../adr/0006-deterministic-engine-platform-capabilities.md)）。

## 实验 1：启动一个最简单的任务（回答问题 1、4）

提示词：`在当前目录创建文件 hello.txt，内容为 ok，然后结束。`

记录：

- 启动命令怎么写（用什么参数传提示词、工作目录、标题、模型）；**提示词很长时能不能用文件传入**。
- 启动后命令是**立即返回**还是**一直阻塞到结束**；返回的内容里有没有任务 ID，格式是什么。
- 任务运行期间，每隔几秒执行一次"查看状态"的命令，把**每一次**输出都保存下来，直到任务结束。目标是看清状态有哪些取值（运行中 / 完成 / 失败 / 等人……）以及输出是不是 JSON。
- `hello.txt` 是否出现在你指定的目录里（而不是平台自己的某个目录）。
- 任务结束后，退出码和最终输出是什么。

## 实验 2：HITL（回答问题 2）

2a 提示词：`先向我提一个问题："你想把文件命名为什么？"拿到回答后，创建一个以该回答命名的文件，内容为 ok，然后结束。`

记录：

- 任务进入"暂停等人"时，状态命令的输出（原样保存）。**请求的 ID、问题文本出现在哪里。**
- 恢复会话、传入回答的命令怎么写；传入后任务是否继续并正确创建了文件。
- 这次暂停发生在**一次回合结束之后**（agent 说完话等你下一句），还是**agent 中途提问、拿到答案后接着干**？用一句话写下你的判断和依据。

2b 重复 2a，但这次**取消**那个等待中的请求，不传回答。

记录：取消之后任务是**继续运行**、**失败**还是**结束**；状态命令此后显示什么；有没有文件被创建。

2c（如果平台有"需要批准才能执行某个命令"的机制）让任务执行一条需要批准的命令，记录批准和拒绝各自的命令与结果。**这和 2a/2b 是不是同一套机制**也写下来。

## 实验 3：控制与并发（回答问题 3、4）

- 能不能**取消一个正在运行**的任务？命令是什么，取消后状态是什么。
- 启动任务的命令有没有这些选项：工作目录、模型、权限/审批模式、标题或标签、"父任务/父会话"。
- 有没有"会话"的概念？能不能向一个**正在运行**的任务发送一条消息而不打断它？
- 同时启动两个任务，两个都能正常结束吗？有数量限制吗？

## 实验 4：用量与认证（回答问题 5）

- 任务结束后，状态、日志或输出里有没有 **token 用量**（输入、输出、缓存）？写下字段名。
- 在**没有人坐在电脑前**的机器上（例如共享开发机、定时任务里）要怎么认证：环境变量名、登录态文件、令牌有效期。只写名字和机制，不写值。

## 交付物

一个文件夹，包含：

```text
exp0-help/            各命令的 --help 输出
exp1-*.txt            启动、每次状态轮询、结束输出
exp2a-*.txt  exp2b-*.txt  exp2c-*.txt
exp3-*.txt  exp4-*.txt
report.md             下面的对照表
```

`report.md` 用这张表回答，每一行写"是 / 否 / 不确定 + 依据文件名"：

| 问题 | 答案 | 依据 |
| --- | --- | --- |
| 状态可查询？取值有哪些？输出是 JSON？ | | |
| 启动命令立即返回还是阻塞？ | | |
| 暂停发生在回合之间，还是 agent 中途提问？ | | |
| 取消请求后任务如何？ | | |
| 能取消运行中的任务？ | | |
| 能向运行中的会话发消息而不打断？ | | |
| 能指定工作目录 / 模型 / 权限模式 / 标题？ | | |
| 有父会话概念？ | | |
| 同时运行多个任务？ | | |
| 报告 token 用量？字段名 | | |
| 无人值守怎么认证？ | | |

## 拿到结果之后

1. 回答填进 [internal-platform-adapter §6](internal-platform-adapter.md)，更新 §2、§3 的映射表。
2. 据此判断适配器走声明式描述还是手写，并写出第一版描述；实验文件作为解释器测试的夹具（用假 CLI 脚本重放同样的输出）。
3. 实验 1、2 的步骤固化为探针集（见 [adapter-guide §5](adapter-guide.md)）。
