# 工作流与分工（5~6 人小队）

- 依据：[plan.md](plan.md)、[ADR 0006](../adr/0006-deterministic-engine-platform-capabilities.md)
- 这里只按**角色**划分，不写人名；谁担任由小队自己定。一人可兼两个轻量角色。

## 角色

| 角色 | 负责 | 产出 | 依赖 |
| --- | --- | --- | --- |
| **A 平台摸底** | 在摸高平台上做[摸底清单](../design/platform-discovery.md)实验 0~4，外加"引擎能否在沙箱里跑"的实验 | `report.md` 与原始输出（脱敏） | 无，最先开始，1~2 小时 |
| **B 基线与环境** | 在能访问 npm 的环境里跑通 req-kit 1.13 的 `typecheck`、`npm test`、`evals`，记录基线 | `evals/baselines/1.13.0.md`、环境说明 | 无 |
| **C 核心搬运与拆耦合** | M1、M2：搬核心、把 Paseo 实现移进适配器、状态 v2、词汇表、CI 平台名检查 | 回归与基线一致的核心 | B |
| **D 内部平台适配器** | M4：依据 A 的结果手写适配器，探针与能力矩阵，一个端到端用例 | 适配器、能力矩阵、探针测试 | A，C（接口稳定后） |
| **E 一致性测试与无头运行时** | M3：`runConformance(adapter)`、无头 CLI 运行时、假 CLI 夹具 | 一致性测试套件、第二个非 Paseo 适配器 | C（运行时接口），A 的夹具 |
| **F 试用场景与对外** | 摸高试用准备：挑选样例需求（含 Java 微服务、React/Vue 前端）、隐藏验收标准、"端到端 20%"的口径、给团队的说明与反馈收集 | 样例集、验收标准、试用方案 | 无，可与 A、B 并行 |

每个角色具体做什么、怎么做、怎么复核、算不算完成，见 [task-cards.md](task-cards.md)。

## 阶段与门槛

```text
阶段 0（并行，先做）  A 摸底   B 基线   F 样例与口径
        │ 门槛 G0：引擎能在哪里运行、状态可查询、HITL 语义——三项有答案
        ▼
阶段 1（并行）        C 搬运拆耦合   D 内部平台适配器   E 一致性测试与无头运行时
        │ 门槛 G1：一致性测试在 Paseo、内部平台上都通过；1.13 回归不退化
        ▼
阶段 2                 摸高首次试用（F 主导，D 支持）：真实需求、隐藏验收、"夸大"为零
        │ 门槛 G2：试用结果按 F 定的口径出数据
        ▼
阶段 3                 生成实验（M5）：LLM 起草适配器，对照手写版本；会话内编排（M6）视情况
```

## 门槛说明

- **G0 不过**：回到 [ADR 0006](../adr/0006-deterministic-engine-platform-capabilities.md) 重新评估引擎位置与 `wait` 实现，D 暂停，C、E、F 继续。
- **G1 要求两个适配器**都通过同一套一致性测试，这是"通用"的证据。
- **G2** 的口径要在阶段 0 由 F 确定，避免试用后再解释数据。

## 协作约定

- 契约（`contracts/agent-runtime.md`）由 C 维护，D、E 提变更需求，不直接改；契约变更同时更新两个适配器的测试。
- 摸底原始输出先脱敏再放进仓库；令牌、内部地址不进仓库。
- 每个角色的产出都带"怎么复核"：命令、期望结果。
- 1.x 缺陷移植按 [compat-migration §3](../design/compat-migration.md) 登记。
