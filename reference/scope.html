范围 ​

laoshi 帮助非专职开发的同事（测试、产品、项目经理等），在本地仓库中，借助任意 agent 平台，把一个需求从对齐做到可验收。

新的提议须同时满足下面三条才会考虑：

  1. 服务于上面这个目标，而不是通用的编码提效。
  2. 至少有两个真实的使用场景。
  3. 无法通过项目配置或项目说明解决。

针对某一个 agent 平台才有意义的能力（例如某平台的插件界面），放在对应适配器里，不进核心。

被拒绝的提议记录在 .out-of-scope/ 中，避免反复讨论。（目录在第一条被拒绝的提议出现时再建。）

本页由仓库中的 SCOPE.md 生成。在 GitHub 上编辑
