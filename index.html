0.2.0-beta.1beta

一句需求，到可验收的功能

在 agent 平台（Paseo、DeepSeek Harness）里用对话把需求谈清楚；一组 AI agent 在后台完成方案、实现、评审和验证；每个要拍板的地方都停下来等你。

$npx -y @yiyi_zhang/laoshi@latest install --platform dsh

只需要 Node.js 22.19+。公司内网只有 npm 镜像时加 --registry=<镜像地址>（会保存为本机的 npm 源）。Windows 上用 cmd 或 Git Bash。

快速开始laoshi 是什么
  1. 对齐你和 AI 对话
  2. 方案AI 写，你确认
  3. 实现AI，质量门把关
  4. 评审另一个模型
  5. 验证按验收标准
  6. 验收你逐条核对
Built for people who own the requirement

每一步都有人把关

测试、产品、项目经理不用写代码，也能把需求做到可验收：AI 做的事看得见，要你决定的事一目了然。

对齐需求

一次一个问题，带选项和推荐

异常情况、权限、测试数据都会问到；确认前另一个模型独立审阅需求说明。

没有数据时，导出按钮怎么处理？

审查原型

在原型上点一点就能提意见

点要改的地方，选"大一点、换颜色、删掉"，用自己的话补一句，自动整理成修改清单。

导出 Excel1
质量门

检查由程序来跑

lint、测试、构建在改动前后各跑一次，只拦新出现的失败，发回给写代码的 agent 修。

代码审查

AI 意见放在对应的行旁边

评审人标"要改 / 不用改"、写自己的意见；退回后流水线按意见修改，再评审、再验证。

验收清单

逐条核对，一键试用

每条写着怎么操作、应该看到什么；在需求自己的工作区里把它跑起来再验。

边界清楚默认打开

推送、发布、连生产，都会被拦下来告诉你

流水线只做本地提交；agent 推送代码、发布制品、改集群、连其他机器的数据库时立即打断，并在对话里通知你。每个改代码的步骤之后扫描密钥，有疑似密钥的分支不会推送。

【需求开发流水线通知】「实现」步骤里，agent 开始运行一条不允许的命令（推送到远程仓库），流水线已经打断了它：
git push origin HEAD:main
